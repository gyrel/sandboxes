# Гайд альфа-тестировщика

Это руководство объясняет, как сообщить о дефекте альфы. Когда что-то идёт не так, одна
команда даёт мейнтейнерам нужную информацию **без утечки ваших секретов**:

```sh
rsbx diagnose --bundle --out gyrel-diagnose.tar.gz
```

## Что внутри бандла

- `manifest.json` — что собрано, размеры, дайджесты и явный список того, что
  пришлось исключить
- `versions.json` — версии CLI и daemon (если daemon доступен)
- `platform.json` — ОС/архитектура, поддержка виртуализации, служебные утилиты
- `config.redacted.json` — настройки **со скрытыми значениями секретов**
- `sandboxes.redacted.json` / `policies.redacted.json` — инвентарь и политики:
  **только счётчики и цели правил**
- `approvals.pending.redacted.json` — ожидающие согласования (идентификаторы и
  метаданные раскрытия, никогда значения)
- `logs/daemon.tail.jsonl` — ограниченный хвост лога daemon (окно 24 часа, ≤2000 строк)
- `errors.json` — сбои коллекторов как классы ошибок
- `README.txt` — этот контракт текстом

## Чего внутри быть не может

Значений секретов, payload хранилища, токенов, приватных ключей, значений
HTTP-заголовков, содержимого workspace, дампов окружения, баз SQLite, снапшотов
и абсолютных путей чужих домашних каталогов (свои схлопываются в `~`). Перед
записью архива каждый байт сканируется на эти формы; **при любом совпадении
бандл отвергается** (rc=1) и файл не создаётся. Отказ намеренный: найденное
не должно покидать вашу машину. Вывод содержит только имя правила и позицию.

Опции: `--sandbox NAME` (один контейнер), `--since 2h` (окно лога),
`--paranoid` (хешировать даже имена песочниц и образов), `--verify BUNDLE`
(пересканировать готовый архив перед отправкой).

## Как завести баг

1. Создайте [issue](https://github.com/gyrel/sandboxes/issues/new?choose=the+template)
   по шаблону **alpha bug report**.
2. Приложите `gyrel-diagnose.tar.gz` и впишите его SHA-256 (`shasum -a 256 …`).
3. Добавьте: ОС/архитектуру, `rsbx --version`, точную команду, ожидание/факт.

Если `--bundle` отказал, приложите вывод отказа (значений там нет) и заводите
issue всё равно. Одно имя правила уже полезный баг-репорт.

## Приватность

Бандл настолько приватен, насколько публичный issue, куда вы его приложите.
Не отправляйте баги с общих машин; если имена песочниц чувствительны —
используйте `--paranoid`.
