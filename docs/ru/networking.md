# Сетевой доступ и порты

Исходящими подключениями управляют daemon и policy gateway. Новые sandboxes по умолчанию используют профиль egress `allow-all`: TCP и UDP к `0.0.0.0/0`, как в базовом поведении Docker `sbx`. Явные deny-правила по-прежнему важнее allow, организационные deny-правила имеют приоритет над локальными, а все fail-closed контроли не меняются. `deny-all` остаётся доступным, и песочница с ним не сможет подключиться к сети, пока правило не разрешит трафик.

## Профиль по умолчанию и правила {#default-profile}

Выберите default-deny для одной песочницы или для глобального значения по умолчанию:

```sh
rsbx run --policy-profile deny-all shell .
rsbx policy init deny-all
rsbx settings set policy.profile deny-all
```

Действующие профили — `allow-all`, `balanced` и `deny-all`; `sbx-compat` принимается как alias для `allow-all`. Выбранный профиль сохраняется вместе с sandbox и показывается в таблице `rsbx ls` и в `rsbx get`.

Правила при создании принимают IPv4 CIDR и необязательный порт. По умолчанию используется TCP; для UDP добавьте префикс `udp:`:

```sh
rsbx run --allow-network 203.0.113.8/32:443 shell .
rsbx run --allow-network udp:203.0.113.53/32:53 shell .
rsbx run --deny-network 203.0.113.0/24 shell .
```

В примерах используются специальные адреса для документации. Замените их только на адреса, нужные задаче. Запрет имеет приоритет над разрешением. Глобальные правила и правила sandbox показывает `rsbx policy ls`.

Доменные правила требуют настроенный DNS upstream и совместимую patched-сборку gateway. Проверка TLS для доменных правил остаётся экспериментальной. Для неё известны ограничения с encrypted ClientHello, UDP только по домену и пересечениями с прямыми IP-правилами. Не используйте доменное разрешение как универсальный DNS- или HTTP-фильтр.

## HTTP-условия {#http-conditions}

Слой политики gateway может дополнительно содержать HTTP-условия в сетевом правиле:

- `method`: точный список без учёта регистра из `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`, `CONNECT` или `TRACE`; `ANY` совпадает с любым method, но оставляет правило только для HTTP.
- `path`: glob абсолютного пути. `*` совпадает внутри одного сегмента, `?` — один символ, поддерживаются классы символов, а целый сегмент `**` совпадает с нулём или более сегментов.
- `query`: упорядоченные требования `name=value`, где значение может использовать тот же glob внутри сегмента. Каждый указанный параметр должен присутствовать; дополнительные параметры разрешены.

HTTP-условия оцениваются по ограниченному request head и никогда не читают body. Условное правило совпадает только с HTTP-запросом, который удовлетворяет всем условиям; UDP-поток или запрос без HTTP-метаданных не совпадает с ним. Невычислимое условие не совпадает и никогда не откатывается к совпадению со всем. Deny-правила оцениваются раньше allow.

Allow и deny с одинаковым selector в одном scope отклоняются типизированной ошибкой конфликта с именами обоих правил. Противоположные дубликаты отклоняются при изменении политики, а не оставляются на разрешение datapath.

Слой политики gateway реализует, валидирует и рендерит эти условия, но локальная surface политики `rsbx` пока не содержит полей `method`, `path` и `query`. Поэтому в этой альфе `rsbx run` и `rsbx policy` не могут создать правило с HTTP-условиями. Live-применение HTTP-условий и CONNECT в datapath `gvproxy` также остаётся непроверенным, поэтому HTTP-правило не доказывает работающий пакетный фильтр.

## Опубликуйте порт

Опубликованные guest-порты привязываются к loopback host-системы и недоступны другим устройствам локальной сети:

```sh
rsbx run --publish 127.0.0.1:8080:3000 shell .
rsbx ports my-sandbox
```

Поддерживаются TCP и UDP. Формы IPv4 и IPv6 loopback доступны на совместимых сборках gateway. Guest-приложение должно слушать адрес, доступный из интерфейса sandbox, обычно `0.0.0.0`.

Публикация порта разрешает соединения с host в гостевую систему. Она сама по себе не разрешает гостю исходящие подключения; при `deny-all` гостю всё равно нужны egress-правила. Настройте их отдельно.

## Просмотр и изменение правил

```sh
rsbx policy ls my-sandbox
rsbx policy allow network --sandbox my-sandbox 203.0.113.8/32:443
rsbx policy deny network --sandbox my-sandbox 203.0.113.8/32:443
rsbx policy check network --sandbox my-sandbox 203.0.113.8:443
```

Локальная команда `policy check` оценивает сохранённые правила. Она не спрашивает gateway и не доказывает, что сетевой пакет будет пропущен. `rsbx policy ls --json` выводит sbx-схему `{"rules":[...]}`; `rsbx policy org` показывает enforced и advisory правила организации.

## Ограничения

Проверки gateway зависят от платформы и сборки. Полная проверка исходящего IPv6, покрытие обходов через QUIC/DoH, live-применение HTTP-условий и независимый security review не завершены. Текущая область проверок описана в [руководстве по безопасности](security.md).
