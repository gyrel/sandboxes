# Docker и Gyrel

Сейчас у Gyrel есть две отдельные функции, связанные с Docker: вход в Docker account на host-системе и экспериментальная настройка для запуска Docker Engine внутри песочницы. Это разные функции. Вход в аккаунт сам по себе не запускает Docker daemon в гостевой системе.

## Текущий статус

**Опциональный профиль запускает Docker daemon внутри guest, но вложенные операции с workload пока заблокированы в текущей альфе.** `docker run`, `docker load`, `docker build` и Compose не проходят настройку вложенной нагрузки из-за запрета `unshare`. Это не означает, что VM не запускается. Профиль не выдаёт guest широкие права на cgroup или capabilities, чтобы эти операции заработали; такой подход был отклонён. Не рассчитывайте на запуск вложенных контейнеров, пока отдельная cgroup-изоляция и минимальный набор привилегий не пройдут проверку и тесты.

## Вход в Docker account

CLI сохраняет авторизацию Docker account через локальный daemon. Альфа также содержит экспериментальный host broker для pull и push Docker Hub из guest. Он прошёл synthetic contract-тесты, но ещё не прошёл live-приёмку в VM и сравнение с той же версией `sbx`. Не считайте его production-ready или parity с Docker Sandboxes. Другие registry этим путём не поддерживаются. Сетевой доступ по-прежнему зависит от политики песочницы: новые sandboxes по умолчанию используют allow-all, поэтому явные deny-правила или профиль `deny-all` могут заблокировать broker.

Чтобы войти через браузер:

```sh
rsbx login
```

CLI покажет код подтверждения и URL. Завершите авторизацию в браузере. Для Docker Hub PAT передавайте токен через стандартный ввод, чтобы он не попал в аргументы процесса:

```sh
read -s DOCKER_PAT
printf '%s\n' "$DOCKER_PAT" | rsbx login --username YOUR_DOCKER_ID --password-stdin
unset DOCKER_PAT
```

`rsbx logout` запрашивает подтверждение и останавливает работающие локальные песочницы перед удалением авторизации Docker account. `rsbx logout --force` пропускает только подтверждение — работающие песочницы всё равно остановятся. Перед подтверждением прочитайте запрос.

## Параметр `--docker`

CLI принимает `--docker` для create/run и включает этим параметром профиль Docker-нагрузки. Профиль привилегированный и может запустить `dockerd`, но вложенные контейнерные операции пока не работают и не прошли security-квалификацию. Наличие параметра в справке не подтверждает, что `docker run` или другие workload-команды выполняются.

```sh
# Experimental: guest Docker workload commands are currently blocked.
rsbx run --docker shell .
```

Поддерживаемый сценарий потребует отдельной cgroup-изоляции гостя, минимального набора capabilities, тестов изоляции, проверок хранилища и жизненного цикла, а также независимого security review. Runtime exec/PTY реализован, но он не включает вложенные контейнеры.

## Отличие от Docker Sandboxes

Docker Sandboxes предоставляет собственный workflow для агентных песочниц и интеграцию с Docker Engine. Gyrel — отдельный проект с локальным microVM-runtime. Совместимость с Docker Sandboxes не заявлена. В текущей альфе остаются незавершёнными вложенные guest workloads, передача registry credentials и production-квалификация безопасности. Перед использованием функции ознакомьтесь с [моделью безопасности](security.md).
