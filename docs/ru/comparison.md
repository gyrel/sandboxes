# Сравнение с Docker `sbx`

Страница сопоставляет Docker `sbx` v0.50.1 и Gyrel `rsbx` 0.0.81 по командам. Каждая строка
описывает, что показывает записанный контроль, и страница перечисляет контроли, нужные для
более сильного статуса.

## Область

| Параметр | Значение |
|---|---|
| Базовый бинарник | Docker `sbx` v0.50.1, SHA-256 `a1e506d1b1f2e17bbc54a3b8e9850592860777689fe3f49098be6279b728c45e` |
| Продуктовый бинарник | Gyrel `rsbx` CLI 0.0.81, SHA-256 `085ec502869ff6c86efacca84af8078a20bd1367f929af496ce007578a1b8669` |
| Release record | daemon 0.0.104, контракт API 0.0.38 |
| Платформа | macOS ARM64 |
| Дата записей | 2026-11-27 |
| Метод | `--help` верхнего уровня, `--help` отдельных команд, `version`, `--version` и пути ошибок валидации аргументов |
| Не проверялось | создание песочниц, запуск daemon, аутентифицированные сценарии, состояние гостевой среды, резервирования портов и применение policy |

Проба запускала оба бинарника с `--help` на верхнем уровне и по отдельным командам, а также
`version`, `--version` и пути ошибок валидации аргументов. Песочницы не создавались, daemon
не запускался, аутентифицированные сценарии не выполнялись. Evidence поверхности не
доказывает runtime parity.

## Словарь статусов

| Статус | Значение |
|---|---|
| `parity` | Одинаковые входные данные дали одинаковый записанный результат на обоих бинарниках под живым контролем. |
| `partial` | Часть поведения поверхности записана; пробелы перечислены в строке. |
| `differs` | Записанное намеренное расхождение; причина указана на странице. |
| `gap` | Не реализовано; принятое ограничение альфы, указано в [ограничениях](limits.md). |
| `unverified` | Реализовано или присутствует, но записанного контроля по одинаковым входным данным пока нет. |

Ни одна строка пока не имеет статуса `parity`.

## Поверхность команд

| Команда | Docker `sbx` v0.50.1 | Gyrel `rsbx` 0.0.81 | Статус |
|---|---|---|---|
| `run` | Help верхнего уровня и `run` сверен. Cloud-флаги включают `--detach-keys` у `run`, `--ttl` и `--volume`. | Локальная грамматика. `--detach-keys` у `run` отсутствует; `--template` — алиас `--image`; `--kit` принимает одну строку. | `unverified` |
| `create` | Полный набор флагов, включая cloud `--image-ref`, `--profile`, `--mount`, `--ttl` и `--volume`. | `--image` заменяет `--image-ref`; `--policy-profile` заменяет `--profile`; `--kit` одиночный; `--skills readwrite` не поддерживается; добавлены `--deny-write`, `--docker` и `--idempotency-key`. | `partial` |
| `exec` | Полный набор флагов, включая `--privileged` и `--detach-keys`. | Набор флагов совпадает. Локальный runtime отклоняет `--privileged`; `--detach-keys` доступен только для cloud. | `partial` |
| `cp` | `-L/--follow-link` следует по symlink и отклоняет выход за пределы workspace. | `-L/--follow-link` следует по symlink верхнего уровня; вложенные ссылки отклоняются. | `partial` |
| `ls` | `--format`, `--json` и `-q/--quiet`. | Те же флаги; добавлен `--limit` (1–1000). | `partial` |
| `stop` | `--format` и `--json`. | Те же флаги; добавлен `--grace`. | `unverified` |
| `rm` | `--all`, `-f/--force`, `--format` и `--json`. | Те же флаги. Без `--force` все указанные песочницы должны быть остановлены, иначе не удаляется ничего. | `unverified` |
| `prune` | `--filter stringArray` (повторяемый), `--dry-run`, `-f/--force`, `--format` и `--json`; секреты очищаемых песочниц удаляются. | `--filter string` (один); `until=TIMESTAMP` или `until=DURATION`; остальные флаги те же; очистка секретов не описана. | `unverified` |
| `ports` | `[[HOST_IP:]HOST_PORT:]SANDBOX_PORT[/PROTOCOL]`; описаны tcp4 по умолчанию, dual-stack loopback и правила cloud. | `[[HOST_IP:]HOST_PORT:]GUEST` с суффиксом протокола `/tcp`, `/udp`, `/tcp4`, `/udp4`, `/tcp6` или `/udp6`; правила протокола по умолчанию и loopback не описаны; раздела cloud нет. | `partial` |
| `kits` | `--kit strings` (повторяемый); локальный каталог, ZIP, Git и OCI; mixins и аргументы kit. | `--kit string` (один локальный kit); remote OCI и mixins отсутствуют. | `unverified` |
| `--cloud` | `--cloud`, `move`, `ttl` и `volume`. | `--cloud` отсутствует. `move`, `ttl` и `volume` зарегистрированы, но возвращают `unsupported` с кодом 1. | `gap` |
| `template` | `inspect`, `load`, `ls`, `rm` и `save`. | Те же подкоманды плюс `export`. | `partial` |
| `mcp` | `add`, `auth`, `inspect`, `load`, `ls`, `rm` и `unload`. | Те же подкоманды плюс `call`. | `partial` |
| `policy approval` | `policy approval` указан с `inspect`, `ls` и `respond`. | `policy approval` сохранён, но скрыт; документированная поверхность — `policy org`. Формы `inspect`, `ls` и `respond` совпадают. | `differs` |
| `secret` | `import`, `ls`, `rm`, `set` и `set-custom`; алиас `secrets`. | Те же подкоманды и алиас. | `partial` |
| `settings` | `get`, `ls`, `set` и `unset`. | Те же подкоманды; описаны `~/.config/rheic/settings.toml` и формат записи settings из sbx. | `partial` |
| `tui` | Команда `tui`. | Команда `tui` присутствует в help верхнего уровня. | `unverified` |
| `login` и `logout` | `login` и `logout` в разделе Other. | `login` и `logout` в разделе Management. | `unverified` |
| формат help | Секции Cobra: Sandbox, Management, Experimental, Other. Неизвестная команда с `--help` печатает help ближайшего предка и выходит с кодом 0. | Добавлена секция Unsupported Docker Sandboxes Commands. `template` переходит в Experimental; `env`, `login` и `logout` переходят в Management; `agents` есть только в rsbx. Неизвестная команда с `--help` выходит с кодом 1. | `differs` |
| `policy ls` | `policy ls` выводит правила allow по умолчанию в таблице `POLICY / SOURCE / APPLIES TO / SUMMARY`. | `policy ls` присутствует; вывод базовых правил не записан. | `unverified` |

!!! info "Имена команд — не evidence"

    Совпадающее имя команды или флага не доказывает совпадение поведения. Флаги, prompts,
    коды выхода, видимое состояние гостя и очистка требуют живых контролей по одинаковым
    входным данным. `rsbx` — бинарник Gyrel; он не занимает имя Docker `sbx`. Границы
    runtime приведены в [ограничениях](limits.md).

## Какие контроли ещё нужны

Проба проверяла только поверхность CLI. Защита от побочных эффектов для `create`, `cp` и
`ports` дорабатывается; ни один записанный контроль этой страницы её не проверяет. Строка
получает более сильный статус только после записи контролей в ledger `docs/controls/ledger.jsonl`.

| Команда | Какие контроли ещё нужны |
|---|---|
| `run` | Контроль по одинаковым входным данным для цикла create, attach и exec; отрицательные контроли для некорректных входных данных. |
| `create` | Проверка состояния для атомарности при kill; отрицательные контроли для `NAME_INVALID` и `AUDIT_CAP_EXCEEDED`; контроль по одинаковым входным данным для грамматики по всему корпусу флагов. |
| `exec` | Отрицательные контроли для кодов выхода 125, 126 и 127 и для `APPROVAL_PROVIDER_UNAVAILABLE`; фикстура кодов выхода по одинаковым входным данным; живой PTY остаётся `gap`. |
| `cp` | Отрицательные контроли для `MEMBER_TYPE_REFUSED`, `LINK_ESCAPE` и `HOST_PATH_NOT_ALLOWED`; проверка состояния для отката по tree hash. |
| `ls` | Проверка состояния для JSON schema; отрицательный контроль для состояния `unknown` при недоступном daemon; контроль маскирования через byte-grep. |
| `stop` | Цикл stop/start по одинаковым входным данным; отрицательные контроли для `NOT_OWNED` и `SESSION_UNREAPED`; проверка состояния для освобождения порта. |
| `rm` | Отрицательный контроль для отказа по каждому элементу; проверка состояния через tree diff с одним удалением; контроль идемпотентного повторного rm по одинаковым входным данным. |
| `prune` | Отрицательные контроли для четырёх классов `UNCLASSIFIED`; проверка состояния для hash всего дерева при abort; diff плана dry-run и реального запуска по одинаковым входным данным. |
| `ports` | Контроль по одинаковым входным данным для 6 канонических и 10 некорректных спецификаций; проверка состояния для таблицы резервирований; отрицательные контроли для `PORT_IN_USE`, `PORT_RESERVED`, `BIND_FORBIDDEN` и `POLICY_DENY`. |
| `kits` | Контроль по одинаковым входным данным для корпуса жизненного цикла kit. |
| `template` | Запись ledger для записанного roundtrip шаблона; контроль по одинаковым входным данным для крайних случаев whiteout. |
| `mcp` | Контроль по одинаковым входным данным для add, list, call и remove; отрицательный контроль для пробела literal-header. |
| `policy approval` | Отрицательный контроль для кода отказа fail-closed; контроль по одинаковым входным данным для пути challenge. |
| `secret` | Отрицательный контроль для отклонения команды-источника; контроль маскирования путей vault и вывода `ls`. |
| `settings` | Контроль по одинаковым входным данным для полного списка имён settings из sbx; отрицательный контроль для `SETTINGS_INVALID`. |
| `tui` | Эквивалент контроля по одинаковым входным данным со скриптовым терминалом: журнал клавиш и дамп кадров. |
| `login` и `logout` | Запись ledger для контроля login/logout по одинаковым входным данным; отрицательный контроль для пробела с именем аккаунта. |
| формат help | Запись ledger с обоими SHA бинарников и артефактом diff до любого утверждения parity. |
| `policy ls` | Запись ledger с закреплённой фикстурой базовых правил. |

## Намеренные расхождения

| Область | Что расходится | Основание |
|---|---|---|
| `policy approval` | Команда сохранена, но скрыта; формы `inspect`, `ls` и `respond` совпадают с `sbx`. | Документированная поверхность approvals — `policy org`. |
| формат help | Неизвестная команда с `--help` выходит с кодом 1 вместо help предка; `template` переходит в Experimental, `env`, `login` и `logout` — в Management; добавлена секция Unsupported; `agents` есть только в rsbx. | Строгая обработка неизвестных команд, записано как намеренное расхождение. |
| `--cloud` | `--cloud` отсутствует; `move`, `ttl` и `volume` возвращают `unsupported` с кодом 1. | Принятый non-goal альфы, см. [ограничения](limits.md). |
| заголовок `mcp` | Записанный пробел в обработке literal header. | Non-goal текущей версии. |

## Evidence и ограничения

Все статусы опираются на контроли, записанные 2026-11-27. Записанные контроли разрешаются в
машиночитаемом ledger `docs/controls/ledger.jsonl`, где хранятся путь и digest каждого
артефакта.

### Записанные контроли

| Контроль | Область |
|---|---|
| `E1-01` | `version` и `--version` на обоих бинарях, с SHA-256 |
| `E1-02` | Инвентаризация секций `--help` верхнего уровня |
| `E1-03` | Пофлаговая сверка для 8 команд |
| `E1-04` | Management-команды: template, mcp, policy, secret, settings, agents |
| `E1-05` | Грамматика `prune --help` |
| `E1-06` | Грамматика `ports` |
| `E1-07` | `run --detach` и detach keys |
| `E3-08` | Неизвестные команды, документированные алиасы, неподдержанные команды |
| `E3-09` | Матрица кодов выхода для пропущенных аргументов, неизвестных флагов и команд |

### Ожидаемые контроли

Записи для текущей пары `sbx`/`rsbx`, которых ещё нет, остаются `pending` в ledger и не
цитируются как evidence. Исторические проверки состояния из предыдущих раундов не закрывают
строки текущей пары. Сессии агентов и аутентифицированные контроли Codex вне этой пробы;
см. [агенты](agents.md) и [ограничения](limits.md).
